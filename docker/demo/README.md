# แอปสำเร็จรูปสำหรับเดโม

```bash
make demo
```

```bash
make demo-offline
```

เปิด http://localhost:8100

| โหมด | ต้องมีอะไร | ใช้เมื่อ |
|---|---|---|
| `live` | LLM + ฐานข้อมูลครบ | ปกติ |
| `replay` | **ไม่ต้องมีอะไรเลย** | เน็ต/GPU ไม่พร้อม · เดโมนอกสถานที่ |

> **โหมด replay คือประกันชีวิตของการเดโม** — เล่น trace ที่บันทึกไว้แบบ stream ทีละตัวอักษร
> เหมือนของจริงทุกประการ ใช้เมื่อ VPN เข้าไม่ได้หรือคิว GPU ยาว

---

## เตรียมก่อนเดโม

```bash
make reseed && make demo-record
```

**ต้อง `make demo-record` ทุกครั้งหลัง `make reseed`** ไม่งั้น trace จะไม่ตรงกับข้อมูลจริง

เอาไปเครื่องที่ไม่มีเน็ต:

```bash
make demo-export
```

## สคริปต์เดโม 12 นาที

### เปิด (1 นาที)

> *"สิ่งที่จะเห็นต่อไปนี้ คือสิ่งที่ทุกคนจะสร้างเองภายในบ่ายวันที่ 3"*

ชี้แถบบนที่แสดงสถานะฐานข้อมูลทั้ง 3 และช่วงเวลาของข้อมูล

---

### คำถามที่ 1 — แหล่งเดียว (1 นาที)

> *"ticket ที่ยังไม่ปิดตอนนี้มีอะไรบ้าง เรียงตามความรุนแรง"*

**ชี้ให้ดู**: เรียก tool ตัวเดียว · ตอบเร็ว · ใช้ token น้อย
**อย่าเพิ่งพูดถึงความซับซ้อน** ให้ผู้ชมเห็นภาพพื้นฐานก่อน

---

### คำถามที่ 2 — ข้ามสามระบบ (4 นาที) ← ไฮไลต์

> *"ทำไมช่วงสองสัปดาห์นี้ถึงมีลูกค้าแจ้งเน็ตหลุดซ้ำๆ หลายราย"*

**หยุดที่แผน** ก่อนปล่อยให้รันจนจบ แล้วอธิบายว่า:
- คำถามไม่ได้บอกพื้นที่ ไม่ได้บอกอุปกรณ์เลย
- AI คิดเองว่าต้องหา ticket ก่อน → เอาอุปกรณ์ไปหาจุดร่วมใน topology → แล้วค่อยดู log

**เปิด step ที่ 1** ให้ดูว่า ticket ทั้ง 5 ใบอยู่คนละ LPE และ **ไม่มีคำว่า APE อยู่เลย**

**เปิด step ที่ 2** — จุดที่พลิกคำตอบ

> *"ข้อมูลนี้ไม่มีทางได้จากระบบ ticket เพราะฝั่งลูกค้ามองไม่เห็นอุปกรณ์ตัวนี้"*

**ชี้ citation ท้ายคำตอบ** — ทุกข้อสรุปบอกว่ามาจากระบบไหน

---

### คำถามที่ 3 — นอกขอบเขต (2 นาที)

> *"ช่วยเขียนอีเมลลาพักร้อนให้หน่อย"*

**ชี้ให้ดู**: 0 tool call · 0 การเรียก LLM · ไม่แตะฐานข้อมูลเลย

> *"คำถามแบบนี้ไม่กิน GPU และไม่แตะข้อมูลลูกค้าเลยแม้แต่แถวเดียว"*

---

### คำถามที่ 4 — เปลี่ยนเรื่อง (3 นาที)

ถามต่อเรื่องอุปกรณ์ 2 ครั้ง → พิมพ์ *"เปลี่ยนเรื่อง ขอดูฝั่งกรุงเทพ"* → แล้วถามย้อน *"เมื่อกี้เรื่องนนทบุรีสรุปว่าอะไร"*

**ชี้ตัวเลขขนาด context ที่ลดลง** ตอนเปลี่ยนเรื่อง แล้วชี้ว่ายังตอบเรื่องเดิมได้จากสรุปที่เก็บไว้

---

### ปิด (1 นาที)

เปิด `apps/mcp-server/TOOLS.md` ให้ดู

> *"ทั้งหมดที่เห็นคือโค้ดไม่กี่ร้อยบรรทัด และเป็นสิ่งที่ทุกคนจะเขียนเองในบ่ายวันที่ 3"*

---

## ข้อควรระวัง

| เรื่อง | เหตุผล |
|---|---|
| `READ_ONLY=true` เสมอ | ผู้ชมอาจพิมพ์อะไรก็ได้ |
| อุ่นเครื่องโมเดลก่อน | `entrypoint.sh` ทำให้แล้ว แต่ควรลองถาม 1 คำถามก่อนเริ่มจริง |
| re-record หลัง reseed ทุกครั้ง | ไม่งั้น replay จะแสดงข้อมูลที่ไม่ตรงกับ DB |
| ใช้คนละ port กับของผู้เรียน | 8100/8180 vs 8000/8080 — เปิดเทียบกันได้ |
