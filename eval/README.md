# การวัดผล

```bash
make eval
```

ต้องรัน `make api` ไว้ก่อน

---

## สิ่งที่วัด

| ระดับ | วัดอะไร | ความสำคัญ |
|---|---|---|
| L0 | Intent Gate ปฏิเสธถูกไหม | ประหยัดทรัพยากร |
| L1 | เลือก tool ถูกไหม | ฐานของทุกอย่าง |
| L2 | วางแผน 2 ขั้นได้ไหม | ความสามารถหลัก |
| L3 | วางแผนข้ามระบบได้ไหม | ความสามารถสูงสุด |
| L5 | ถามกลับเมื่อกำกวมไหม | ประสบการณ์ผู้ใช้ |
| **L6** | **กล้าตอบว่าไม่รู้ไหม** | **วัด hallucination โดยตรง** |
| L7 | Guardrail ทำงานไหม | ความปลอดภัย |

> **L6 ตกถือว่าร้ายแรงกว่า L1 ตก** — เลือก tool ผิดคือช้า แต่แต่งคำตอบคือทำให้คนเชื่อสิ่งที่ไม่จริง

---

## ให้ผลเทียบกันได้ข้ามครั้ง

```bash
DEMO_NOW=2026-01-15T10:00:00+07:00 SEED_RANDOM_SEED=42 make reseed
```

ถ้าไม่ตรึงเวลาและ seed ข้อมูลจะเปลี่ยนทุกครั้ง แล้วจะแยกไม่ออกว่าคะแนนที่เปลี่ยนมาจากการปรับปรุงระบบ หรือมาจากข้อมูลที่ต่างกัน

---

## ผลลัพธ์

`eval/results/latest.json` — เก็บไว้เทียบข้ามครั้ง แนะนำให้ commit ไฟล์นี้ทุกครั้งที่ปรับระบบ

## ต่อยอดสำหรับติดตามผลครั้งที่ 2

หลักสูตรระบุ BLEU / ROUGE / User Satisfaction — เพิ่มได้โดย:

1. เขียนคำตอบอ้างอิงในฟิลด์ `reference_answer` ของแต่ละคำถาม
2. เพิ่มการคำนวณด้วย `sacrebleu` และ `rouge-score`
3. **อ่านข้อจำกัดของ BLEU/ROUGE ก่อน** ที่ [../instructions/reference/evaluation-metrics.md](../instructions/reference/evaluation-metrics.md)
