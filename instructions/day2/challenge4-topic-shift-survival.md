# โจทย์ที่ 4 · Topic Shift Survival

**16:00 – 16:30** (30 นาที) · ปิดท้ายวันที่ 2

---

## เป้าหมายการเรียนรู้

พิสูจน์ว่า agent ของคุณรอดจากบทสนทนาจริงที่ผู้ใช้เปลี่ยนเรื่องไปมา โดยวัดจาก **กราฟขนาด context** ไม่ใช่จากความรู้สึก

---

## สถานการณ์

เจ้าหน้าที่ NOC ใช้ระบบทั้งกะ คุยเรื่องหนึ่ง แทรกเรื่องอื่น แล้วย้อนกลับมาเรื่องเดิม ถ้า context โตตลอด ระบบจะช้าลงเรื่อยๆ และเริ่มลืมสิ่งที่คุยไปตรงกลาง

---

## สิ่งที่ให้มา

บทสนทนา 10 turn ที่ `data/questions/L4-conversation.yaml` (`CONV01`) — เปลี่ยนเรื่อง 3 ครั้ง

| turn | เนื้อหา | สิ่งที่ต้องเกิด |
|---|---|---|
| 1-4 | เรื่อง NBI | สร้างหัวข้อ ใช้ context ต่อเนื่อง |
| **5** | *"แถวนี้มีร้านอาหารแนะนำไหม"* | **นอกขอบเขต แต่ห้ามล้าง context** |
| **6** | เปลี่ยนไปฝั่ง BKK | **ตรวจจับได้ + context ลดลง** |
| 7-8 | เรื่อง BKK | ใช้ context ใหม่ |
| **9** | *"เมื่อกี้เรื่องนนทบุรี สรุปว่าอะไร"* | **ตอบได้จากสรุป ไม่ค้นใหม่ทั้งหมด** |
| 10 | ส่งสรุปให้ NOC | ครอบคลุมทั้งสองเรื่อง |

---

## สิ่งที่ต้องทำ

1. รันทั้ง 10 turn ผ่าน agent ของตัวเอง
2. หลังทุก turn เรียก `GET /sessions/{id}/memory` แล้วบันทึก:
   - `context_tokens`
   - `topic.label`
   - `topic_changes`
   - จำนวน tool ที่เรียกใน turn นั้น
3. วาดกราฟ `context_tokens` เทียบกับหมายเลข turn
4. วิเคราะห์ว่าจุดไหนเป็นไปตามที่ควร จุดไหนไม่

---

## เกณฑ์ผ่าน

- [ ] **turn 5**: `tool_calls == 0` และ `topic` ไม่เปลี่ยน และ `context_tokens` ไม่ลดฮวบ
- [ ] **turn 6**: `topic_changed == true` และ `context_tokens` ลดลงจาก turn 5 อย่างน้อย 40%
- [ ] **turn 9**: คำตอบต้องมีคำว่า `APE-NBI-03` และเรียก tool ไม่เกิน 1 ครั้ง
- [ ] กราฟ `context_tokens` **ไม่ใช่เส้นที่โตขึ้นตลอด** ต้องเห็นจุดที่ลดลง
- [ ] turn 2, 3, 4 ไม่ถามกลับว่า "หมายถึงอะไร" (ต้องใช้ context เดิมได้)
- [ ] 10/10 turn ไม่มี exception

---

## โบนัส

1. **หา threshold ที่ดีที่สุด** — รันทั้งชุดที่ threshold 0.4 / 0.55 / 0.7 แล้วรายงานว่าค่าไหนพลาดน้อยที่สุด พร้อมบอกว่าพลาดแบบไหน (ตัดทิ้งทั้งที่ไม่ควร vs ไม่ตัดทั้งที่ควร)
2. **เพิ่ม turn ที่ 11** — ผู้ใช้กลับไปเรื่อง NBI เต็มตัว ระบบควร restore หัวข้อเดิมกลับมาไหม ออกแบบและอธิบายเหตุผล
3. **ต่อ long-term memory** — เก็บข้อสรุปลง pgvector แล้วเริ่มเซสชันใหม่ ถามคำถามเดิม ระบบต้อง recall ได้
4. **เทียบกับ agent ที่ไม่มี memory management** — ปิดกลไกทิ้ง แล้วรันชุดเดิม เทียบ token รวมและเวลาที่ turn 10
